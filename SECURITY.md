# Security policy

## Repository classification

This repository must remain **private**. It contains a generic demonstration application and synthetic sample data only.

## Prohibited content

Never commit or enter:

- Employer-confidential or non-public information
- Client, employee, applicant or personal data
- Production records, communications or metadata
- Credentials, access tokens, API keys, certificates or passwords
- Security findings, vulnerabilities, architecture diagrams or internal endpoints
- Regulatory submissions, legal advice or investigation material
- Real incidents, control failures, risk acceptances or audit evidence

## Controls

- Keep GitHub repository visibility set to private.
- Enable two-factor authentication on the repository owner account.
- Do not enable public Pages or public forks.
- Review collaborators and deploy keys regularly.
- Use sample data only unless the application is moved to an approved enterprise environment.
- Run a secrets scan before each release.

## Reporting

If sensitive information is committed, immediately make the repository inaccessible, revoke exposed credentials, remove the data from Git history and follow the relevant incident process.
